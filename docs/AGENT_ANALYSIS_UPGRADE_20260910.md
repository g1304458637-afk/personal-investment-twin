## Stability changes

1. The legacy structured correction pass now receives the preceding schema-valid option selection, rather than reconstructing the complete selection from a rejection code alone. Product-fixed `answer_focus` is materialized locally; conflicting provider values still fail. Evidence, numeric binding, ClaimOption and counter-material checks remain.
2. The old live failure record did not retain its malformed field. Its exact historical field therefore remains unknown. New diagnostics retain only allowlisted field names, failure class, correction stage and safe path—not model text, values, financial records, prompts or credentials.
3. The owned Episode page routes its primary analysis action to the common scoped conversation. The duplicate legacy input is removed for owned real/showcase Episodes; notes and prior interpretations remain. Shared/pair/old synthetic workflows retain their existing consented review path and are not silently widened into account chat.
4. The new technical cache does not overwrite normalized daily-price cache entries. Cache hits retain the original data retrieval time. Current-date/unclosed bars are excluded from completed-bar indicators; out-of-range/future/invalid rows make data quality explicit.
5. Fundamentals retrieval is bounded below the outer DSA tool timeout; default statement requests use a bounded worker pool and retain statement-level failures. A fixed, allowlisted public-service failure may produce a service-status receipt, never a market-data receipt. The answer can explain unavailable service rather than infer that the company has no data.
6. Dynamic public/research/owned-analysis references are validated against the actual tool-call receipt ledger in backend and frontend. Account and Episode scope, cache keys, archives and source fingerprints remain separate.

### Defects found by real QA and fixed afterward

- **One correction could uncover a second hidden error too late.** Numeric validation and semantic review now inspect the same reference-valid first candidate before the single correction. Unread references, wrong scope and invalid schema still fail before semantic review. A positive model verdict cannot erase a pending numeric failure.
- **Correct record explanations were mislabeled `concept`.** Writer instructions distinguish general knowledge from a fact about a requested calculation/status. Repair feedback points at the specific paragraph and its actual record kinds; the validator never automatically relabels unsupported prose.
- **Empty navigation falsely rejected; comparison IDs falsely mismatched.** Empty guides cannot acquire an invented model-only navigation failure. Nonempty guide findings are preserved even if the model contradicts itself with a positive boolean. Canonical/display aliases are supplied only for actually read owned Episodes; public record fields cannot authorize private Episode navigation.
- **Calendar date choices failed exact valuation boundaries.** The period adapter resolves requested calendar ranges to their first/last complete actual observation days, retaining requested, effective and available dates plus observation counts. Existing financial and behavior engines still calculate the results, with explicit `(effective_start, effective_end]` behavior semantics. No holiday valuation is invented.
- **Percentages already expressed in percentage units were rejected.** Period records now include formatting-only `display_metrics` from existing results: percentage levels use `%`, differences use percentage points, HHI and fees retain their units. Raw comparison precision is unchanged. Common three-decimal numbers and four-decimal percentage displays are also accepted by the formatting guard; this is not a new financial formula.
- **A numerically rejected result paragraph could leave only definitions.** Available technical records expose deterministic display values. `technical_result_findings` checks that explicit result-seeking questions actually report a cited indicator value in both languages; parameters, dates, unrelated numbers and incompatible units do not count. It is a minimum content check, not proof that every possible question is fully answered. The final implementation no longer deletes rejected paragraphs to manufacture a passing answer (see the design review below).
- **Ordinary number/date formatting was misread.** Thousands separators are now parsed as groups of three digits, so MACD parameter lists are not concatenated into one number. ISO timestamps permit their original clock components in normal display form; no timezone conversion is invented. Marked open-Episode PnL is explicitly distinguished from unrealized PnL on the remaining shares: the former can include earlier realized partial exits.
- **OHLC teaching overstated what a candle contains.** Knowledge and verification now explicitly distinguish open/high/low/close from the unknown intrabar path; long bodies and short wicks do not establish small intrabar drawdowns.
- **Diagnostics themselves gave false negatives.** The live harness now checks for real numeric technical outputs, period results and natural non-overlap wording, not just tool names. A same-stock answer that correctly said “没有重叠的投资期间” was initially rejected by the harness's narrower wording list; the list and isolated regression were corrected. That was a QA assertion defect, not a financial-engine defect.

### Mature-pattern review and final output policy

Following the user's request to look for established solutions, the local flow was compared with [Pydantic AI output validators](https://pydantic.dev/docs/ai/core-concepts/output/) and [LangChain structured-output error handling](https://docs.langchain.com/oss/python/langchain/structured-output). Both document concrete validation feedback followed by another model-produced structured output. Pydantic AI explicitly separates its bounded output retry budget; LangChain supports choosing the error classes or feedback handled by its output strategy. These are architectural references, not newly installed dependencies or claims that either framework guarantees financial truth.

Decision: preserve the existing pinned DSA runner and one semantic correction, aggregate defects on the same initial candidate, and revalidate the entire corrected output. Remove the local post-correction paragraph-deletion fallback. Live manual review found it could remove an announcement's introduction while leaving “the same announcement”, or retain only some requested technical results. A positive judge over the remainder did not make that transformation reliable. If the second complete candidate still fails numeric binding, return the existing controlled failure instead of publishing a reconstructed answer. Regression tests cover both dangling references and RSI/MACD partial deletion, including a falsely positive mock judge.

The format-level retry also previously repeated the original request with a generic “return JSON” instruction. It now uses Pydantic's structured validation errors to feed back bounded code-owned paths, type codes, local structural constraints and the untrusted previous candidate. The existing SDK validation remains the success criterion; no new permissive JSON repair or stricter success-path type gate is introduced. The candidate is held only on the current schema instance, consumed within the same authorized model process, and cleared; diagnostics retain only allowlisted paths/types, never candidate content. The original two format attempts, input-size bound, consent checks and legacy fixed-field semantics remain. This is a direct application of specific validator feedback, not another Agent framework.

Real QA subsequently identified `$.paragraphs[0..3].text` / `model_type`: the model had supplied plain strings where the existing bilingual object was required. The bounded format repair resolved that shape. The same run then exposed a separate scope error in our free-prose count matcher: “the first two purchases” was incorrectly compared with the entire Episode's three purchases. The matcher now emits a bounded count-mention observation for the existing semantic verifier to resolve, rather than deciding natural-language scope by regular expression. A missing ledger total remains unknown, never zero. Source references, financial number binding and schema validation remain hard gates. The reviewer also distinguishes increasing held quantity from non-monotonic purchase quantities (400 → 300 → 400).

The [DSA release notes](https://github.com/ZhuLinsen/daily_stock_analysis/releases) describe timeout, cancellation and bounded-concurrency work. The **local pinned** `dsa_vendor/tools/execution.py` already contains cooperative cancellation and non-retriable timeout support. Release notes alone are not grounds to overwrite the pinned vendor directory; they also do not make already-running third-party blocking requests forcibly cancellable. Provider transport hardening remains separately identified below.

Final-output targeted checks: **92 passed** after numeric/date formatting changes; **38 passed** after removing paragraph deletion. These runs overlap and must not be added together as unique tests. A subsequent final combined regression is recorded separately when complete.

With whole-output validation enabled, fresh live checks returned complete technical values (including MACD, RSI, ATR and volume ratio) in **34.026 seconds**, and an independently readable Bocha event summary with sources in **20.456 seconds**. Neither answer was assembled by dropping a failed paragraph. Earlier eight-case machine PASS results that still used paragraph deletion are not used as the final manual-quality acceptance result. The subsequent combined backend regression passed **148 tests in 320.89 seconds** before the specific schema-feedback change; that change has its own targeted results rather than being retroactively included in this run.

## Remaining acceptance before installation

Live QA was authorized and performed as described above. The rebuilt packaged sidecar, embedded-payload consistency and local signature checks passed. A full native-window acceptance of desktop restoration and the common entry flow remains after permission to replace/restart the installed application. Browser preview and offline routing tests do not substitute for that native acceptance. No old installed bundle may be presented as containing these source changes.

Remaining quality limits: first financial-context preparation and restart context verification are still slow, as measured above. Some live answers are still longer than desirable; a finite successful smoke run is not a production success-rate measurement. Technical completeness detection is intentionally conservative for elliptical follow-ups and guarantees at least one substantive result, not every requested metric by itself. Provider statement waits are bounded, but an upstream blocking request already running in the fixed worker pool cannot be forcibly cancelled; repeated provider stalls remain a transport-hardening follow-up. No new dependency or alternative model client was introduced during this QA pass.

Not included: automatic execution, full upstream strategy suite, real-account pretrade engine extension, strategy Lens historical evaluation, full fundamental valuation model, professional/private comparison network, scheduling or push delivery. Saved retrospective notes remain in the original review workflow; this task does not claim the new DSA toolset reads those notes.
