# 投镜复盘回答标准 v1：先明确价值，再调整 Agent

状态：目标答案与离线事实基准；不是已上线 Agent 能力，也不是生产回答模板。
日期：2026-09-06。本文件不替代既有金融、Evidence、ClaimOption 或授权合同。

## 1. 本轮交付与验收边界

只定义三类问题：结果形成、关键操作、持仓暴露。答案示例使用既有 Synthetic
输入，通过现有 replay / Outcome / HHI builder 核验；不得放进 UI 冒充模型回答。
不改 prompts、tools、provider、runtime、金融算法、前端或 generated payload。

- `tests/fixtures/review_answer_targets_v1.json`：固定事实期望值、来源与问题级验收案例。
- `tests/test_review_answer_targets.py`：重放真实合成输入，核对期望值和失败状态。
- 数字测试通过只证明目标答案有事实基础；不证明 Agent 能回答，也不证明用户理解。
- 示例允许等价措辞，不做逐字匹配或靠关键词命中宣称语义验收通过。

## 2. 用户第一层答案

先直接回应问题，再展示至多两三件相关发现，最后有条件地提供一个检查点。
用户可以点击“查看这次操作”“查看这项历史对比”；链接必须绑定当前投资的具体对象。
不默认展示可折叠证据目录、Evidence ID、Method Version、模型名称或工具运行记录。
内部仍保留全部事实引用和审计链。

专业表达不是反复说“不知道”，也不是隐藏影响理解的限制：先说已证实内容，
用自然语言交代历史假设、比较期间、估值日和 Synthetic 来源。没有计划证据时，
不编造动机；只有计划会改变问题判断时，再问一个非诱导性问题。

## 3. 目标答案 A：结果形成

问题：这轮为什么亏损？
范围：Demo Security H，Synthetic，2025-01-06 至 2025-05-20。

> 本轮最终亏损 283.50 元。已有历史对比显示，2 月 20 日的加仓值得先回看。
> 在下一次操作前、统一按 3 月 17 日市场价估值，实际账面结果为 −770.50 元；
> 只取消该次加仓的局部历史对比为 −256.00 元，相差 514.50 元。
> 但不能把所有操作都看作拖累：3 月 18 日的减仓，在它对应的下一操作前比较中，
> 实际结果比取消减仓少亏 48.00 元。
> 这些对比针对不同历史区间，不能相加当作最终亏损的拆分。

收获：定位一个可核对的操作影响，而不是把亏损归结为性格。
检查点：回看 2 月 20 日扩大持仓时的资金安排；这不是建议以后停止加仓。

要求：

- 最终已实现结果与局部账面结果分别命名。
- −770.50 是截至比较估值点的 Position 结果，不是从加仓日开始的区间损益。
- 514.50 是指定假设下的差额，不是加仓贡献占比、纯市场效应或最终少亏金额。
- 取消操作也移除该笔记录费用；其他纳入操作保持原样，下一次及后续操作不纳入。
- 不能直接从 Position Return 与 Asset TWR 的差异推导 Entry/Exit/Sizing 原因。
- 缺少同期合格 benchmark 时，回答可支持的操作影响，不编造行业或市场归因。

## 4. 目标答案 B：关键操作

问题：如果 2 月 20 日没有加仓，最后是不是能少亏 514.50 元？

> 514.50 元对应的是下一次操作前的历史对比，不是最终结果。
> 这项对比按 3 月 17 日市场价估值，实际为 −770.50 元，取消该次加仓为 −256.00 元。
> 如果要求一直保留之后每笔原数量卖出，取消这次加仓会让后续卖出数量超过可用持仓，
> 因此不能把这个假设延伸成整轮最终少亏金额。

收获：知道一笔操作影响了哪个范围，避免事后制造“早知道就好了”的假最优答案。

要求：

- 明确下一次操作是 3 月 18 日 10:05；估值用 3 月 17 日 daily mark，不伪装成盘中报价。
- 不静默缩减后续卖单以使完整期间假设可运行。
- 不跨不同终点排名“最坏操作”；选择回看案例不等于证明它是唯一或最大亏损原因。
- 回答“是不是每次减仓都错了”时，必须保留 3 月 18 日局部比较的相反事实。
- “上涨后加仓”是时序事实，不能自动变成“追涨”“贪婪”。

## 5. 目标答案 C：持仓暴露

独立范围：`synthetic_behavior_executions.csv` + `synthetic_behavior_prices.csv`，
2025-01-08 的多资产 Synthetic 快照。它不是 Demo Security H 的账户，禁止跨示例拼接。

问题：我持有五只证券，是不是已经足够分散？

> 这个示例当时持有 5 只证券，但比例并不均匀：最大一项占证券市值的 67.24%，
> 前三项合计占 88.51%。仅看持有数量，会漏掉这种分布差异。
> 这里不包含现金，不能把 67.24% 当作整个账户的仓位；这些数据描述集中程度，
> 不直接判定你的风险是否过高，也不要求把最大持仓降到某个比例。

内部核验：HHI = 0.4817677368212446，method = hhi_security_weights_v1，
一个快照 observation，不是 5 个历史样本。HHI 不要求在第一层文案中展示。

收获：区分证券数量、证券内部权重和账户资金占比。
检查点：在后续有账户全量权重与原资金安排时，再连接决策前模拟核对拟交易后的暴露。

要求：

- 本轮没有增加行业、基金底层成分、相关性、波动或完整风险模型。
- 不把未知行业暴露填成 0，不把 HHI 值称为风险评分。
- 完全平仓、无正证券市值时，HHI 为 insufficient / None，不伪造 0 或宣称无风险。
- 同一证券继续加仓可能改变账户权重却不改变证券内部 HHI；没有相应事实不能推断。

## 8. 验收规则

自动事实门：使用同一 Synthetic 输入调用现有 engine；金额、时点、范围、状态、
counterfactual 双侧与 HHI 分母一致。黄金值不能由测试启动时自动覆盖。

人工语义门：fixture 的每个 case 分别检查 required_meanings 与 forbidden_claims，
不能靠否定句中出现敏感词就误判。以下任一发生即失败：

- 发明数字/引用，使用未读取或越账户的事实；有 ref 但不支持其叙述。
- 局部差额解释整轮损益，跨终点相加，费用重复扣除，实际与假设状态混淆。
- 未支持的心理事实、能力评分、未来预测或具体买卖指令。
- 在回答“不都是减仓造成的”时故意省略相关相反事实。

用户价值门：用户看完能说出“发生了什么”“哪项操作值得看”“依据针对哪段历史”。
答案直接回应问题，不要求先打开技术折叠区才能理解；检查点可选，不强行造建议。

真实模型门（待后续实施）：每个 case 至少重复运行三次记录波动，全部保持事实与语义边界；
不得用离线脚本替代真实 DeepSeek 回答验收。不得未经授权发送真实账户数据。

评估方法参考 [OpenAI：Evaluate agent workflows](https://developers.openai.com/api/docs/guides/agent-evals)：
区分工具链过程与任务结果。本项目采用本地基准，不新增托管评估依赖，不上传账户数据。
