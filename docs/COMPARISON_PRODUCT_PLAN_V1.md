# 投镜三种对比：产品问题、数据、计算与页面方案 v1

日期：2026-09-07。性质：讨论稿 / 实施规划，不是新金融合同或功能完成声明。

本次核对基于主仓库 HEAD `0ef7856` 及当前 working tree。现有未提交工作保持不变。

## 1. 设计前提与产品目标

按用户确认的前提设计：所需完整成交、账户状态、资金流、行情、专业组合和当时计划等数据均可获得。接口采购、券商合作、同步方式不是本次功能设计的约束；数据定义仍必须明确。此假设不表示这些数据或能力已经接入。

只保留三个对比板块：

| 板块 | 用户核心问题 | 完成后的收获 | 主要选择器 |
| --- | --- | --- | --- |
| 自我前后对比 | 我的投资方式发生了什么变化？ | 看见结果、配置、操作的变化，并找到具体实例 | 自己的账户 / 两个时期 |
| 同一只股票对比 | 同一只股票，两个人为什么走出了不同经历？ | 看清差异发生在哪个阶段、哪次操作及其历史结果 | 股票 / 两轮投资 |
| 与专业人员全盘对比 | 我的整体投资方式与这个专业组合有什么不同？ | 理解收益背后的风险、资金安排和操作方式 | 专业对象 / 共同期间 |

共用阅读顺序：**结果差异 → 配置差异 → 操作差异 → 深入解读**。不做能力总分、投资考试、排行榜式的默认结论。不新增第四个 Peer/Cohort 板块。

第一层是清楚的结论、数字和图形，而非技术字段。Agent 不重复朗读指标列表；每个分析条目都能返回支撑它的日期、持仓或操作。

## 2. 一套完整数据输入

以下是目标输入，不是要求用户逐项手填。目标展示版将采用后端生成的完整 Synthetic 研究账户；未来文件或券商接口提供同样的事实。当前示例仅覆盖已经实现的行为、Episode等事实，尚无本方案所述完整账户绩效与公司行为链路。

| 数据组 | 所需字段与含义 | 主要用途 |
| --- | --- | --- |
| 账户身份 | 所有者、账户、币种、授权范围；专业对象还需明确基金/份额类别/具体策略及任职时期 | 不把个人、单账户、基金和某位经理全部历史混成一个对象 |
| 期初状态 | 期初时点、现金、各证券数量、成本与来源；或足够完整的更早历史以重建状态 | 正确开始任意期间，不能裁剪成交后从空仓重新算 |
| 成交事实 | 证券唯一标识、时间/时区/精度、canonical sequence、方向、数量、真实成交价、已记录费用 | 复用现有 canonical execution / replay |
| 资金与公司行为 | 入出金、证券转入转出、分红、拆并股、相关费用/税和生效时间；明确账户边界 | 区分本金变化、内部投资收入与投资收益，防止重复记账 |
| 估值与基准 | 证券价格、日期、价格口径、来源版本；账户估值；基准总回报序列；如涉及多币种则需对应 FX | 收益、回撤、风险、估值与同期背景 |
| 历史配置 / 穿透 | 直接持仓；基金成分、权重、有效日期和披露时间；行业/地区分类历史 | 穿透图、行业/地区对照、重叠持仓 |
| 当时计划 | 原始计划内容、记录时间、后续修改、适用操作和用户授权 | 区分当时计划、实际执行与事后解释；不把事后补记当当时动机 |
| 专业对象资料 | 数据来源、账户/产品边界、投资范围、杠杆、费用口径、绩效系列及持仓披露覆盖 | 选择合适对象与可比范围，不仅按事后收益挑赢家 |

行情复权、现金分红、拆股数量必须协调处理，不能把同一公司行为既体现在复权价格又在账户现金/数量里重复计算。数据齐全不等于会计与价格口径自然一致。

## 3. 自我前后对比

### 3.1 用户路径

选择账户 → 选择两个时期 → 阅读主要变化 → 点击变化查看真实案例 → 询问 Agent。

默认产品比较单位为最近两个完整的三个月区间，以已完整覆盖的数据截止日为锚点，明确显示真实日期，不默认为电脑今天。月份按日历计算。窗口归属、期初/期末估值和事件计入约定由新的期间汇总方法统一固定。

同一页提供“当前在我的历史中”作为次级视角，复用已有 3m / 12m / lifetime 基线；它不是“两个时期”统计的替代品。

### 4.2 同区间绩效的明确处理

保留 v1：共同区间用于观察价格和操作，双方完整期 PnL/Return 独立展示。

“统一期间结果”若实施，新增独立版本化分析，不能改写 v1：

- 本方案优先以双方共同期间的**全账户绩效作为背景**，明确不是单股操作成绩。
- 单股投资子组合收益只有在明确资金边界、归属现金、流入流出及估值约定后另立方法；不从峰值数量、完整期 Position Return 或裁剪后的价格线推导。
- 共同开始前的持仓/现金状态必须保留；原始成交顺序不变。
- 资金规模不同，不以货币盈亏绝对大小判优劣；共同比较日的账户仓位仍是描述，不等于风险完全相同。

现有授权分享仅限 Episode 派生事实。假设全数据可取得，不代表该旧权限自动扩展到对方全账户；需要的范围必须在未来接入中显式说明。

## 6. 计算口径表

本节分清“冻结方法复用”和“待实施的方法设计”。公式说明不等于授权修改现有金融合同。生产计算仍优先复用已有 vectorbt replay 与已安装的 empyrical；不得在 React 中另算账户、成本、收益、HHI 或反事实。

### F1 账户时间加权收益（待补账户级方法）

以外部资金变动分段：`r_j = V_j_end_before_flow / V_j_start_after_previous_flow - 1`，每段内部没有外部入出金。

`TWR = product(1 + r_j) - 1`；展示净值 `NAV_t = 100 × product_{j<=t}(1+r_j)`。

此公式的精确模式要求每次外部资金流紧邻之前和之后的估值，不是随意选取当天两个价格。建议新方法以“期间起点外部流之后”和“期间终点外部流之前”的明确估值状态作边界，期间内部每笔外部流单独分段，首尾资金不得再重复调整。同一时刻资金流和成交的先后需有源顺序证据；最终边界必须以时间、事件顺序和流前/流后阶段固定，并加入验收样例。以上是待确认的新账户方法设计，不改变既有 canonical execution 排序。

需要资金流前后可用估值及明确费用/收入口径。账户内部买卖不是外部入出金；股票或子组合边界不同会改变资金流分类。仅有日价格时必须先固定日级资金流处理方法，不发明盘中估值。正账户价值范围内先实施；非正值/杠杆另行定义，不直接套用。

同一期基准使用总回报或明确的一致价格口径。费用后账户收益、基金份额净值和未扣费指数的区别在对象描述中一次说明，不能把基金管理费差异隐去。此项不等同于已有 Asset Episode TWR。

### F2 最大回撤与恢复时间（待补账户绩效投影）

`peak_t = max(NAV_s, s<=t)`；`drawdown_t = NAV_t / peak_t - 1`；`MDD_magnitude = -min(drawdown_t)`。

UI 最大回撤使用正幅度，回撤曲线为非正值，符号不得混淆。使用 F1 的资金流调整净值，不以原始余额计算。恢复时间从所选回撤的前高到首次重新达到此前高点；尚未恢复则展示“截至日期仍未恢复”，不能填零。日频数据只能声称观察频率下的回撤。

### F3 收益差（待补比较投影）

`difference_pp = 100 × (R_user - R_reference)`。两个输入用同一完整期间；这是百分点差，不是相对收益百分比、Alpha 或能力归因。自我两期收益各自计算，不把不同时长累计收益直接当改善程度。

### F4 配置与集中度（现有公式复用）

`account_weight_i = security_value_i / total_account_value`，现金作为账户配置的一项。

当前 HHI：`w_i = security_value_i / sum(risky_security_values)`；`HHI = sum(w_i²)`，不含现金。Top1/Top3 复用现有 builder 输出。不把账户扇形图的含现金权重代入原 HHI 方法。直接 HHI 与未来穿透 HHI 若都需要，必须是不同方法/指标，不更换分母却保留旧名称。

### F5 换手强度（现有公式复用；期间汇总待补）

`daily_turnover_d = sum(abs(filled_quantity × execution_price) on d) / end_of_day_account_value_d`。

分子双边成交金额、不含费用；分母含现金。期间日均值仅对该窗口内合法的已有 daily observations 做算术平均；只有完整观测日确实无交易时是零，源数据缺日不能补零。显示有效观测日期范围，不能把这个值冒充基金披露的年换手率。两日之差不是两个季度之差。

### F6 盈亏持仓处理（原方法复用，事件窗口需单独版本化）

`PGR = realized_gains / (realized_gains + paper_gains)`；`PLR = realized_losses / (realized_losses + paper_losses)`；另展示 `PGR - PLR`。

`loss_averaging_rate = qualifying_loss_state_additions / eligible_additions_to_existing_positions`。

分子/分母使用现有 builder 对 SELL、paper opportunity、BUY 的冻结定义。按期计算仍需完整前缀状态；不把期初持仓当零，不把各期百分比直接平均，不将累计比率差替代窗口比率。零分母与零事件严格分开。

### F7 个人历史位置（现有 Self v1 原样复用）

`percentile = 100 × (count(history < current) + 0.5 × count(history == current)) / N`。

P25/P50/P75 使用 `numpy.quantile(..., method="linear")`；`delta = current - median`。滚动窗口是日历月 `[T-window,T)`，并排除被选为当前状态的那一条观测。HHI 最少 3 个、Turnover 最少 5 个合格观测；这是既有可用门槛，不是统计显著性。

历史按真实观测等权，不是按持续时间加权；只纳入同所有者/范围和同方法版本的有效证据。Self midrank 不替换为现有 Peer 的 `scipy_percentileofscore_rank_v1`。专业单对象比较也不凭空制造 percentile。

### F8 穿透配置（待新增派生层）

`underlying_weight_j = direct_account_weight_j + sum_f(account_weight_f × constituent_weight_fj)`。

直接持有和通过不同基金间接持有的同一资产合并；展开后不再同时把基金本体计入同一层总额。嵌套基金按明确深度处理，循环引用不能无限展开。现金、未分类和未覆盖部分保留为独立项，不能把已知部分重新归一化后声称全覆盖。

行业/地区是对底层权重的分类汇总；归属采用该日有效的分类。披露生效日与公开可知日分别保存，历史决策解释只使用当时已可知版本。目标实现先限定普通 long-only 配置，不把衍生品名义金额和市值比例混在同一饼图。

### F9 历史操作假设（现有方法原样复用）

读取现有 `comparison.pnl_difference`，当前答复实现方向是 **counterfactual minus actual**；符号和文案一起保留，不另外计算或悄悄取反。

Actual 和 CF 继续由同一 replay 产生。保留 scenario_id/version、execution boundary 与 valuation observation。strict pre-decision v2 使用决策日期之前的合法 daily mark；不修改 v1 历史方法或 Exit fixed-window 口径。重叠反事实不能加总成最终损益拆分；原数量后续成交不可行时，不自动缩量造结果。

### F10 波动和风险调整收益（待新增统计投影）

在等间隔完整日收益下：`annualized_volatility = sample_std(daily_returns, ddof=1) × sqrt(K)`。

`Sharpe = mean(r_d - rf_d) / sample_std(r_d - rf_d, ddof=1) × sqrt(K)`；K 是按市场/频率固定的方法参数，rf 是同币种同频率无风险收益。不得对不规则稀疏点硬套 252；零波动不输出无穷大分数。先复用并验证已安装库的实现及符号。

产品默认以期间收益和回撤为主；年化与 Sharpe 只在规定的数据频率和足够覆盖下进入次级展示，短样本不做机械外推，也不把比值当能力评分。

## 7. 页面内容与交互

三页共用透明玻璃视觉，不新增视觉方向。资金比例、时间序列和操作内容使用现有 ECharts/时间导航体系。

| 层次 | 自我前后 | 同一只股票 | 专业全盘 |
| --- | --- | --- | --- |
| 顶部选择 | 账户、两个时期；切换个人历史视角 | 股票、A/B Episode、共同观察段 | 专业对象、共同期间 |
| 首屏摘要 | 结果/配置/操作三类主要变化 | 双方完整期结果、期间、操作路径 | 同期收益、回撤、配置差异 |
| 主图 | 两期净值、配置双图、历史指标 | 一条价格与两条操作/持仓轨道 | 同期净值与回撤，双配置/穿透图 |

选择指标后联动日期/操作，不跳到泛 Evidence 列表。价格、成本、数量、账户权重保持不同单位。专业对象名称、真实期间和数据身份在第一层可见，method/trace/raw ID 不默认展示。

第一屏只突出有依据的内容；无对应结果不填假值也不铺满免责声明。影响解读的条件用紧贴结果的一句话表达，例如“双方各自完整投资期”或“持仓披露截至某日”。详细证据仍在系统保留，供核验，不强迫普通用户阅读。

## 8. Agent 的输入、输出与权限

输入：用户问题、当前选择范围、已计算的 comparison findings、可用图表锚点、实际读取的证据/假设和同期计划。不是把全部账户原始数据一次丢给模型。

输出规划：一个回答用户问题的摘要，最多 2–3 个主要发现，每项附具体数字/日期和可跳转操作；用户可以继续追问。不增加一个单独展示技术日志的区域。

分工：

- 后端计算数值、可比范围、分子分母、假设结果和证据引用。
- Agent 选重点、联系上下文、解释术语、区分事实与可能解释。
- 当前 `ClaimOption`、tool receipt audit、structured finalization 和 claim/evidence verification 原样保留。新比较条目通过受限视图接入；未定义的自由生成契约不作为本方案已解决事项。
- 数据齐全也不自动证明心理因果；同期计划可以支持计划执行分析，价格之后发生的买入不能直接升级为“贪婪/追涨事实”。
- 不自动生成复制对方交易的指令，不把对比结果变成综合能力分。方法限制主要由正确内容选择和措辞承担，不靠首屏堆警告。

## 10. 实施顺序与展示版里程碑

1. **口径冻结与验收样例**：确认上述问题/指标矩阵；固定账户绩效、期间归属、分项贡献的输入输出和 hand-calculated fixtures。旧合同不动。
2. **自我对比接齐现有能力**：3m/12m/lifetime、真实历史图和案例导航；明确“当前对历史”与“两期比较”。
3. **共享绩效 / 配置薄层**：先验证固定资金的完整 Synthetic 组合，再覆盖明确的入出金、期初持仓/公司行为样例；穿透数据和日期单独验证。无法由现有 replay 正确支持的输入不能以新手写引擎绕过。
4. **两期结果与同股完整体验**：补期间统计；同股保持完整期结果和共同过程对照，接对象选择与可解释差异，不为填页面编造统一收益。
5. **专业全盘展示闭环**：使用明确标注的 Synthetic 研究组合，完成收益/风险/配置/操作全链；模拟组合不冠以真实专业人士姓名或声称代表专业人群。
6. **Agent 比较解读**：将已验证条目接入既有分析和验证链，用问题驱动展示；之后再替换数据来源和券商接口。

演示状态必须能区分“后端已算出的 Synthetic 结果”和“尚未计算的功能预览”，不能只用一个含糊 Demo 标签掩盖差别。本轮仅规划，不启动以上代码实施，不自动 commit/push。

## 11. 验收用例

| 用例 | 必须观察到的结果 |
| --- | --- |
| 无收益变化，仅增加外部本金 | 账户余额增加，TWR净值不因此上涨 |
| 无价格变化，仅出金 | 余额减少，不制造投资回撤 |
| 分红与拆股 | 统一处理后可与权威余额/持仓核对，不重复计入复权与现金/数量 |
| 同一组事实打乱输入集合顺序 | 结果与标识稳定；同一时刻成交仍按 canonical sequence |
| 向历史数据追加未来成交/行情/披露 | 过去的 point-in-time 结果不变 |
| 两期长度/覆盖不同 | 实际日期与观测口径保留，不以交易总数直接宣称更频繁 |
| 稀疏行情或缺失必要价格 | 不 forward-fill、不补零收益/换手、不硬套日频年化 |
| HHI现金与证券权重 | HHI复用不含现金方法，账户扇形图含现金仍能核对总额 |
| 相同数值的历史 ties | Self仍为既有midrank；不误换Peer算法 |
| 亏损追加零分母 vs 有合格事件但零发生 | 前者无比率，后者合法0；窗口前状态保留 |
| 同股不同完整期间 / Open与Closed | 结果带各自期间/类型，不能当共同期收益排名 |
| 取消操作导致后续卖出不可行 | 原方法返回不可行，不自动改变后续数量 |
| 多项反事实都影响同一操作链 | 不相加为最终亏损贡献，保留各自情景与估值时间 |
| 直接+两只基金重复持有同一股票 | 底层合并；基金本体不重复计入；未知部分保留 |
| 只有专业净值而无成交的输入变体 | 仍可展示合法绩效；不生成买卖点和成本 |
| Agent 引用未读取或其他范围的事实 | 既有验证拒绝，不能通过流畅文字绕过 |
| 页面中英文、透明材质、键盘与缩放 | 关键数字清楚，同色同义；点击差异到准确日期/操作 |

产品验收：用户30秒知道双方是谁、比较什么期间；2分钟能指出至少一项具体配置/操作差异；5分钟能打开该差异的原始投资过程并提出有针对性的追问。不要求用户读懂method ID、N/CI或内部Evidence结构才能获得价值。
