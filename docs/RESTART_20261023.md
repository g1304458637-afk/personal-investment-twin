## 这批修好了什么

| 问题 | 修复后的行为 |
|---|---|
| 示例模式可能运行真实账户、切账户后显示旧策略结果 | 按模式、账户、策略内容、来源修订、运行标的池绑定结果；切换后拒收晚响应，允许重新运行 |
| 前端等 300 秒、后端 30 秒后可能误杀全部任务 | 产品请求统一为宿主 300 秒、界面 330 秒；单数据线程有序读写 SQLite，独立控制通道回应健康检查 |
| 排队写入在界面超时之后还可能执行 | 宿主附执行期限，工作线程开始前再次检查；排队过期不执行。已经开始的写入若超时，明确提示结果尚未确认，先重读数据再操作 |
| “为什么”按钮找不到 Python 方法 | 接通已有策略教学实现，增加 Python/Rust 方法清单一致性验证；模型验证使用替身，不进行付费调用 |
| 空白手续费变成零费用 | 空白总额或不完整分项保留 unknown；明确填入的数值 0 才是 explicit_zero |
| 买入持有基准漏现金、拆股被当成亏损 | 晚上市前资金保留现金；按时间处理拆股、退市和最后可见价格。基准披露无费用、无滑点、允许碎股，区别于策略净收益 |
| 同一个 EMA 在不同入口算出不同数值 | 统一为前 N 个收盘均值播种、第 N 根起输出，再按 2/(N+1) 递推；公式、条件、公共技术分析共用实现 |
| 行情指纹只包含数量和日期 | 单标的和多标的路径改为规范化行情内容哈希，覆盖 OHLCV 和实际提供的来源等字段；价格变动会改变指纹 |
| 年度账户与复盘包其实来自两个示例 | 新复盘包从同一年度账户输入生成，并验证账户、来源指纹和 Episode 对应关系；旧独立研究样例保留 |
| 真实行情仿真仍显示合成标签，公式敏感度入口无效 | 修正数据标签和限制说明，对未支持的敏感度路径明确限制 |
| 行情缓存写在源码/解包临时目录 | 宿主注入 AppData/cache；独立 Python 使用系统用户缓存；缓存写入失败不丢弃已成功取得的行情 |
| 账户事实库权限过宽 | 新建及重新打开时收紧数据库和相关文件为 POSIX 0600；宿主专用 AppData 为 0700，不修改无关父目录 |

内置 4 套策略、共 8 个 JSON 结果同步重新生成。逐字段核对确认策略订单、成交、日净值和费用不变，只修正基准曲线、相关绩效指标和口径说明。相同示例的基准首日净值从错误的 937,500 修复为 1,000,000；末值从 1,216,040.68 修复为 1,262,680.12。因此原来显示的超额收益会下降，这属于纠正计算。
